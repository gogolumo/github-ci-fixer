# GitHub CI Fixer Free

**Find the real reason your GitHub Actions failed. Fix it with confidence.**

An offline diagnostic tool and Agent Skill by **Bohdan Dron**. Analyze a saved GitHub Actions
text log, get a focused evidence-based hypothesis, and follow a specific verification procedure.
Free is useful on its own. No GitHub account, paid API, backend or runtime pip dependency.
Not every CI failure can be diagnosed or fixed automatically.

## What it does

- Recognizes tested Python/pytest, npm/JS/TypeScript, Rust, dependency, environment, path,
  permission, workflow rejection and unavailable-command signatures.
- References physical log lines and retains gh job/step prefixes.
- Separates warning candidates and secondary exit markers from meaningful errors.
- Emits actionable Markdown with missing context and truthful **not-run** verification status.
- Bounds input size, escapes active Markdown/HTML and redacts common credential formats.

## Install and use

Requires Python 3.11+. Clone/download this public repository, or extract the Free ZIP into a
folder named `github-ci-fixer`. Keep SKILL.md, scripts, references and examples together.
On Windows, use `python` if `python3` is unavailable.

```text
git clone https://github.com/gogolumo/github-ci-fixer.git
cd github-ci-fixer
python3 free/github-ci-fixer/scripts/ci_fixer.py fixtures/python_missing.log
```

For agents, point your host at [SKILL.md](free/github-ci-fixer/SKILL.md), or install that complete
skill directory using the host's documented Agent Skills installation mechanism. The scripts
also work directly without an agent. This release does not assert universal agent compatibility;
see [validation status](docs/VALIDATION.md) for actual environment tests.

Analyze your own saved **UTF-8 text** log by passing its path as the positional argument.
Capture stdout if you want a Markdown file. Exit 0 means analysis completed, not CI passed;
exit 2 means invalid/unreadable input. ZIP logs and binary files must first be exported to text.

```text
Assessment: signature-supported. Verification: not-run.
F1: Python import failed
Hypothesis: The runner cannot resolve an import; dependency, import path or version may differ.
Evidence: python_missing.log:1: ModuleNotFoundError: No module named 'requests'
Status: not-run. This is a recommendation, not a tested repair.
```

## Limits and privacy

Rules identify observed signatures, not a unique proven root cause. First observed error may
follow omitted failures. Unknown, empty and truncated logs need more evidence; a failing assertion
does not establish whether the code or test is wrong. No code changes or tests are performed by
Free. Input is limited to 8 MB; lines to 16000 characters and findings to 100.
Secret redaction is best effort; personal/source fragments may remain. Review before sharing.
Offline scripts make no network requests. Your AI host has its own data/network policy.
See [security policy](SECURITY.md), [architecture](docs/ARCHITECTURE.md) and
[research](docs/PRODUCT_RESEARCH.md).

## Develop and build

```text
python3 -m venv .venv
python3 -m pip install -r requirements-dev.txt
python3 -m unittest discover -s tests -v
python3 tools/benchmark.py
python3 tools/build_release.py build free/github-ci-fixer release/github-ci-fixer-free-1.0.1.zip
```

Activate the virtual environment before the pip/check commands: `source .venv/bin/activate`
on macOS/Linux, or `.venv\Scripts\Activate.ps1` in Windows PowerShell. See
[contributing](CONTRIBUTING.md) for lint/type/format and audit commands. ZIP builder produces a
SHA-256 sidecar and validates root layout, links, unsafe paths, secret signatures, sizes and an
extracted trusted-package smoke. This is submission preparation, not Agensi approval.
